## Highest-value audit findings outside Claude's current Writer mission

### F1 — Private flagship and unattended production still use different Writer brains

The private certification lane directly uses canonical Writer V2.1 via `quality_certification_retry.py` / `writer_v21_orchestrator`.

The unattended production quality loop in `generate.py` still calls legacy `generate_candidate(...)`. `generate_candidate_v2(...)` exists as a canonical V2.1 delegate, but no production callsite was found on this audit base, and `render.yml` does not activate a V2.1 cutover variable.

**Implication:** a successful private flagship does not prove scheduled daily production is using the same Writer. A deliberate champion-to-production cutover is still required after V2.1 earns promotion.

### F2 — Failed private flagship attempts do not train topic selection

`quality_certification_generate.select_topic('auto')` deterministically ranks fresh eligible facts from production memory. Private failed attempts do not update that production memory. A failed top-ranked topic can therefore be selected again on the next auto flagship unless another state signal changes.

The selector also asks for recent treatments from memory, but current production memory entries inspected in `memory_science.json` do not persist a `treatment` field. Thus recent-treatment avoidance is not reliably load-bearing on the current state.

**Implication:** attempt history/failure history needs its own durable ledger. Do not overload production memory.

### F3 — Current memory conflates recent dedup state, learning state, QA history, and candidate history

`generate.py::save_memory()` truncates history to the last 14 entries. Generation writes the entry before render, and enqueue mode writes an entry even though the manifest has not yet rendered. `main.py` later attempts to attach final QA to the matching entry.

This is useful short-window operational memory, but unsuitable as durable learning memory.

**Implication:** build an append-only attempt/certification ledger separate from recent operational memory. Keep small derived summaries for runtime token efficiency.

### F4 — Script buffer is not a Delivery Guarantee

`buffer.yml` banks pre-generated manifests, not finished certified MP4s. It can create multiple scripts while provider capacity is fresh, but downstream rendering/visual/audio QA may still fail later.

**Implication:** long-term reserve must consist of finished, certified videos with expiration/freshness metadata, not scripts.

### F5 — Legacy script queue creates cutover contamination risk

Queued manifests are generated by the currently active production Writer. If Writer V2.1 later becomes canonical while old queued manifests remain, the renderer can dequeue pre-cutover legacy scripts unless queue entries are versioned/validated or cleared.

**Implication:** any Writer cutover needs queue schema/version/certification compatibility and an explicit migration policy.

### F6 — QA can diagnose visual defects but cannot yet execute the repair loop

Private workflow creates `holistic_qa_report.json` and `targeted_repair_plan.json`. `quality_postrender_review.py` maps major/critical defects to exact time windows/scenes and recommends smallest-bounded repair. However `automatic_repair_authorized` is false and no workflow step executes a repair/re-render/re-QA cycle.

`video_repair_lab.py` exists with preservation contracts and hard budgets but remains a manual/experimental lab.

**Implication:** Quality Guarantee is stronger than Delivery Guarantee today: the system can reject a mostly-good video but cannot autonomously salvage its one bad scene.

### F7 — Holistic final QA is static-frame based

`final_video_qa.py` samples 9 frames and groups them into 3 contact sheets. That can detect wrong subjects, bad text, visual mismatch, repetition, and gross continuity problems. It cannot directly observe motion quality, transition timing, caption timing, narrator prosody, music dynamics, or temporal editing rhythm from static images.

`quality_audio_qa.py` independently checks mechanical audio mastering (stream, LUFS, peak, silence, WPM) but explicitly requires human listening and does not judge voice performance.

**Implication:** current QA is valuable but not a full viewer-experience judge. Avoid treating its pacing/continuity scores as ground truth for temporal experience.

### F8 — Premium visual architecture exists mostly as plans, not runtime

`visual_director.py` has strong evidence-first visual classes. `quality_runtime.py` currently executes NASA SVS / RCSB / PubChem and delegates other lanes. `generated_media_controller.py` has explicit promoted-model + cost + independent-vision-QA contracts, but it is plan-only. Private flagship disables FAL, generated visuals, ElevenLabs, and SFX.

**Implication:** several quality-stack modules exist but are not load-bearing in the flagship factory. Integrate only after the free/authentic path is proven, using scene-level escalation rather than AI-everything.

### F9 — Visual relevance has been the dominant historical downstream defect

Historical human review repeatedly found wrong or weak footage despite acceptable scripts: generic lab imagery for nitinol, children/rose footage for vacuum exposure, cement mixers/blue chemicals for pitch drop, loosely related BCI footage, abstract city graphic for methane deposits, wrong rodent/species, cheesy emoji/CGI on abstract topics, and jargon/visual mismatches.

Later fixes improved subject naming and banned obvious metaphor/emoji footage, proving visual-director constraints materially improve quality.

**Implication:** Visual Intent + cross-scene continuity + actual final-asset lineage are high-payoff next-stage work, not cosmetic polish.

### F10 — Final-asset provenance is incomplete for legacy moving footage

The quality bridge records scientific candidates and whether a NASA video candidate was considered/injected, but the legacy renderer remains final moving-footage selector. `used_footage_science.json` persists only IDs, not scene intent/query/source/winner/relevance/QA outcome.

**Implication:** failure learning and continuity need a richer per-scene asset ledger describing the asset that actually rendered.

### F11 — Scheduled provider spend can happen on the legacy production path

`render.yml` schedules two provider-backed runs/day. `buffer.yml` schedules a daily buffer fill of up to six manifests. Both currently call the legacy production generation path. Publishing is disabled, but generation spend/quota consumption is independent of publishing.

**Implication:** after funding Gemini, scheduled legacy generation may consume budget/capacity and may bank legacy scripts before V2.1 production cutover. This is a control-plane decision, not a publishing risk.

### F12 — Production prerequisites still contain an old slow font probe

The fast `fc-match` prerequisite repair was merged into the private flagship workflow. `render.yml` still contains the older `fc-list | grep -qi dejavu` / apt path.

**Implication:** the same false/slow prerequisite pathology can still affect unattended production even though private certification was fixed.

### F13 — Performance-learning loop is nearly data-starved

`perf_science.json` currently contains only four old July examples. The code has performance weighting for watch-through/follows/saves/shares/comments, but there is not enough current labeled outcome data to drive robust selection.

**Implication:** human preference + real platform analytics ingestion should be treated as a data product, not assumed to already be a learning loop.

### F14 — Documentation is materially stale

`CLAUDE.md` still says free-tier-only / no paid keys, contains historical provider assumptions, and does not yet capture PR #72/run #5/current Gemini funding. This is dangerous because Claude uses it as session bootstrap.

**Implication:** update after the active Claude engineering mission so new session state reflects reality.

### F15 — `main` is not branch-protected on the audited repository state

The live branch metadata reported `protected: false`. Existing workflows intentionally commit state directly to `main`, so protection must be designed around that operational reality rather than enabled blindly.

**Implication:** lower-priority integrity hardening is warranted after the active factory work; do not break state-writing workflows accidentally.
